# docs/methodology.md

Fortune-OS の方法論（v0.1）。実際の分析手順。

---

## 1. 分析のパイプライン

```
[事実] 収集
  → [計算済] 占術データの計算（出典明記）／未計算なら未計算と宣言
  → [占術解釈] 体系ごとに読む（矛盾は併記）
  → [推測] 仮説化（占術外の推論も含む）
  → [現実照合] 経歴・行動・成果と突き合わせ
  → [反証] 反する事実・外れ条件を探す
  → [信頼度] 確信度を付ける
  → 意思決定の選択肢に変換
```

各段階でタグを維持する。後段が前段を上書きしても、前段は消さず `[反証]` として残す。

---

## 2. データの3階層

1. **一次情報**（本人申告・記録）＝ `[事実]`
2. **導出データ**（計算した命式・ホロスコープ）＝ `[計算済]`（出典必須）
3. **解釈**（占術・心理モデルによる読み）＝ `[占術解釈]` / `[推測]`

階層をまたぐときは必ずタグを切り替える。

---

## 3. 占術体系の扱い

- 各体系は独立に読む（`astrology/bazi.md`, `western_astrology.md`, `six_star_style.md`）。
- 体系間の矛盾は `astrology/compatibility.md` や本文で**併記**。統合して1つの結論にしない。
- 時刻依存の要素（時柱・ASC・ハウス・月の度数）は、出生時刻が未検証なら信頼度を一段下げる。

---

## 4. 現実照合のやり方

- `user/subject.md` §4・`user/wife.md` §4 の実データを主材料にする。
- 占術解釈ごとに「当たっている点／外れている点」を明示。
- 外れた解釈は捨てず、外れログとして残す（v0.4 で仕組み化）。

---

## 5. 意思決定への変換

分析の出口は必ず**選択肢**にする。
- 断定（「独立すべき」）ではなく、
- 条件付き選択肢（「Aの条件が揃えば独立検討、Bなら保留、判断のトリガーはこれ」）。

`strategy/decision_framework.md` の枠組みを使う。

---

## 6. レビューと更新

- 出力は `system/quality_rules.md` のチェックリストで自己採点。
- 大きな意思決定の後、実際どうだったかを記録し、読みの精度を振り返る（`ROADMAP.md` v0.4〜）。
