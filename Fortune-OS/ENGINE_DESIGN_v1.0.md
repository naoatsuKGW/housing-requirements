## 1. 分析の目的

Fortune-OS の目的は**未来予測ではなく意思決定支援**である（`docs/philosophy.md` §4、`CLAUDE.md` §1）。
対象は次の4領域（`user/priorities.md` §2 のコア4テーマに対応）：

| 本書の表現 | 対応するコア4テーマ |
|---|---|
| 自己理解 | （全モジュール共通の土台。特定テーマに紐づかない） |
| キャリア | ①仕事（独立適性・組織との関係を含む） |
| 人間関係 | ③夫婦関係 |
| 人生戦略 | ②創作・技術探究、④人生後半戦 |

**成果指標は「当たったか」ではなく「意思決定の質が上がったか」**（`docs/philosophy.md` §4）。
自己理解は独立した第5のテーマではなく、心理学モジュール（§3）が他の4テーマ全てに供給する基盤レンズと位置づける。

## 2. 分析パイプライン（正典・9ステップ）

```
Step1 入力         … user/subject.md・user/wife.md・user/priorities.md から対象者情報を取得
Step2 計算         … knowledge/calculation_config.md の設定・SOURCE_POLICY.md の優先順位に従い、
                     各占術モジュールが値を算出。出典3点（ツール名・バージョン・算出日時）必須。
                     算出できない値は「未計算」のまま次段へ渡す（`CLAUDE.md` §3-3）
Step3 事実抽出     … [事実] タグ。user/*.md の一次情報のみ。占術・推測と混ぜない
Step4 占術的解釈   … [占術解釈] タグ（体系名必須）。四柱推命・西洋占星術・（将来）六星系等が
                     独立に読む。体系間の矛盾は統合せず両論併記（§4）
Step5 心理学統合   … [推測] タグ中心。心理学モジュール（Big5・認知バイアス・ストレスパターン）が
                     占術とは独立したレンズとして評価。占術解釈を心理学で裏打ちしない
Step6 現実照合     … [現実照合] タグ。user/*.md §4 の実際の経歴・行動・成果と突き合わせ
Step7 反証         … [反証] タグ。意識的に反証を探す。見つからない場合もその旨を明記
                     （見つからない＝検証不足の可能性、`system/output_rules.md` §2）
Step8 信頼度評価   … [信頼度:高/中/低] ＋ 定量スコア（§5）。Step4〜7の結果を合成
Step9 行動提案     … `strategy/decision_framework.md`（移行後は `plugins/strategy/engine.md`）の
                     型で、選択肢・トリガー条件・撤退条件に変換。断定にしない
```

**タグとの対応：** 各ステップの出力は既存7タグ（`docs/glossary.md` §2 が正典）のいずれかに必ず属する。
本パイプラインは「タグをどの順で生成するか」の手順であり、タグの定義そのものを再定義しない。

**体系間の一致率評価について：** Step4とStep8の間で暗黙に発生する「複数占術モジュールの一致率」は、
独立したステップとして切り出さず、**Step8（信頼度評価）の内部計算**として扱う（§5で詳述）。
これにより `logs/ARCHITECTURE_REVIEW_v0.9.md` 草案にあった「Step4一致率評価」は本書で統合・整理された。

## 3. 各分析モジュールの役割

### 3-1. 四柱推命（BaZi）
- **役割：** 年月日時の四柱・日主強弱・用神・大運/年運から、気質の骨格と時間軸の傾向を読む
- **入力：** 出生年月日時・出生地（`knowledge/calculation_config.md` §1・§3の設定に従う）
- **出力タグ：** Step2で`[計算済]`（柱そのもの）、Step4で`[占術解釈]`（意味づけ）
- **現状：** `astrology/bazi.md`（移行後 `plugins/bazi/engine.md`）。全データ未計算

### 3-2. 西洋占星術
- **役割：** 出生図（太陽・月・ASC・MC・10天体・ハウス・アスペクト）から、意識・感情・対外的な出方の傾向を読む
- **入力：** 出生年月日時・出生地（トロピカル・Placidus基準、`calculation_config.md` §2）
- **出力タグ：** Step2で`[計算済]`（度数・サイン・ハウス）、Step4で`[占術解釈]`
- **現状：** `astrology/western_astrology.md`（移行後 `plugins/western/engine.md`）。太陽サイン概算以外未計算

### 3-3. 心理学
- **役割：** Big Five・認知バイアス・ストレスパターン・愛着スタイル・ユング的視点から、占術と独立したレンズで気質・強み・過負荷パターンを評価
- **入力：** `user/*.md` §4 の実データ（現状は多くが未記入）。データが乏しい間は`[推測]`に留まる
- **出力タグ：** 主に`[推測]`。`[現実照合]`が入るまで断定しない
- **現状：** `psychology/*.md`（移行後 `plugins/psychology/`）。占術解釈を心理学で裏打ちしない・混ぜない原則を維持（`psychology/personality.md` 冒頭）

### 3-4. キャリア理論
- **役割：** 専門深化vs拡張、所属vs独立、技術vsマネジメントの軸で、独立適性・組織との関係を整理する現実材料主導の分析
- **入力：** `user/subject.md`（職業・関心）、家計材料（`strategy/finance.md`）
- **出力タグ：** `[事実]`・`[推測]`・`[現実照合]`中心。占術は補助レンズに留める（`strategy/career.md` §5）
- **現状：** `strategy/career.md`（移行後 `plugins/strategy/career.md`）

### 3-5. 行動科学
- **役割：** サンクコスト・現状維持・確証バイアス・プランニングファラシー等、意思決定を歪めるバイアスの検出
- **入力：** Step9（行動提案）の直前に適用するチェックリスト
- **出力タグ：** `[推測]`（バイアスの疑い）。断定・診断ではなく注意喚起
- **現状：** `psychology/cognitive_bias.md`（移行後 `plugins/psychology/cognitive_bias.md`）

**モジュール間の独立性：** 各モジュールは他モジュールを直接参照しない。統合は Step8（信頼度評価）と
Step9（行動提案）でのみ行う（`logs/ARCHITECTURE_REVIEW_v0.9.md` §1 の依存方向反転の原則を継承）。

## 4. モジュール間で矛盾した場合の優先順位

矛盾が起きたとき、次の順で扱う（上位が下位を上書きする）：

1. **現実照合（Step6）が最優先。** 実際の経歴・行動・成果に反する解釈は、どれだけ複数の占術体系が一致していても信頼度を上げない（`docs/philosophy.md` §3「現実照合が最上位」）
2. **反証（Step7）があれば、その解釈の信頼度を下げる。** 反証を無視して結論を確定しない
3. **占術体系間（四柱 vs 西洋 vs 将来の追加体系）の矛盾は、統合・一本化しない。** 両論併記する（`system/system_prompt.md` §5）
4. **占術と心理学の矛盾も同様に両論併記。** 心理学は占術の裏付けにも反証にも使われるが、優先されるのは常に現実照合
5. **どの階層でも判断材料が無い場合、信頼度は「低」に据え置く。** 情報不足を「中」に格上げしない（`system/quality_rules.md` §4）

## 5. 信頼度スコアリング（v1.0 正式版）

`logs/ARCHITECTURE_REVIEW_v0.9.md` §4 の草案を正式化する。

### 5-1. モデル
論点ごとに、関与する各モジュールの読みを「一致／部分一致／不一致」で評価し、合成する。

```
論点：（例）独立適性は高いか
- 四柱推命       ：一致 / 部分一致 / 不一致 / 未計算
- 西洋占星術     ：一致 / 部分一致 / 不一致 / 未計算
- 心理学         ：一致 / 部分一致 / 不一致 / 未評価
- 現実照合       ：（存在すれば最優先。他の全評価を上書きする重み）

配点：一致=1.0、部分一致=0.5、不一致=0
合成：現実照合が無い場合は各モジュールの単純平均→一致率(%)
      現実照合がある場合、現実照合の結果が一致率を上書きする
```

### 5-2. 信頼度の上限ルール
- **現実照合データが無い論点は、一致率が100%でも信頼度の表示上限を「中」に制限する。**
  （`system/quality_rules.md` §4「信頼度を盛らない」の定量化）
- 星取り表示は補助として使ってよいが、**★5（最高）は現実照合込みで全モジュール一致の場合のみ**。
- 未計算のモジュールは合成対象から除外し、「未計算のため一致率算出不可」と明記する（除外を隠さない）。

### 5-3未決定事項
- 部分一致の重み（0.5固定か可変か）、モジュール数増加時の合成式（単純平均か加重平均か）は
  `logs/DECISION_LOG.md` 形式で別途決定する。本書では決定しない。

## 6. 行動提案生成ルール

Step9の出力は、`strategy/decision_framework.md`（`CLAUDE.md` §7「迷ったときの原則」準拠）の型に従う。

1. **問いを一文にする。**（例：「今年度中に独立を進めるか」）
2. **選択肢は最低3つ。** 二択に閉じない。「進む／保留／第三の道」を必ず含む
3. **各選択肢に4項目を付す：** 可逆性・最悪ケース・撤退条件・トリガー条件
4. **占術・心理学は単独の根拠にしない。** `strategy/finance.md`・`strategy/career.md`等の現実材料が主
5. **保留は正式な選択肢。** 「何が分かれば決められるか」を明記する（先送りと区別する）
6. **過負荷期（`psychology/stress_patterns.md`）には不可逆な大決定を勧めない**
7. 出力は`strategy/decision_framework.md` §6の決定ログ形式で残し、後日の答え合わせ（現実照合）に使う

## 7. 絶対にやってはいけないこと（要約参照）

> **正典は `LIMITATIONS.md`（12項目）・`system/safety_rules.md`・`CLAUDE.md` §3。**
> 内容の重複を避けるため、本書では複製せず、エンジン設計として特に注意すべき項目のみ抜粋する。

- 計算していない占術データを`[計算済]`と偽らない（`CLAUDE.md` §3-3）
- 未来を断定しない。傾向・リスク・選択肢の言葉に留める（`CLAUDE.md` §3-2）
- 占術・心理学モデルを唯一の根拠に重大な意思決定をさせない（`LIMITATIONS.md` §1-11）
- 人格を否定しない。対象は常に行動・選択・構造（`CLAUDE.md` §3-4）
- 医療・法律・財務の確定助言をしない（`safety_rules.md` §1）
- 単独ツール・単独情報源の値を無検証で確定値扱いしない（`SOURCE_POLICY.md` §6）
- 危機的兆候（自傷・他害等）に対して分析を継続しない。専門的支援へ接続する（`safety_rules.md` §6）

詳細・全項目は必ず `LIMITATIONS.md` を参照する。本節はその入口に過ぎない。
