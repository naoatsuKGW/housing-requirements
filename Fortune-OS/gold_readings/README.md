# gold_readings/

Fortune-OS **Gold Standard Reading 集**（v1.0）。

> 本ディレクトリは仕様・QA基準文書であり、7レイヤータグの適用対象外（`CLAUDE.md` §2 の精神に準拠）。
> ただし配下の `GOLD_NNN_*.md`（実例）自体は分析出力そのものであり、**7レイヤータグの適用対象**。

---

## 1. これは何か（誤解防止）

**Gold Standard Reading は「占い結果」ではない。**
`ENGINE_DESIGN_v1.0.md` に定義したエンジン設計が、実際に高品質な分析を生成できるかを検証するための、
**エンジンの理想出力（品質基準の実例）**である。

- 目的は本人を楽しませることではなく、**「これ以下の品質の出力を作らない」という下限を固定すること**
- 今後、`templates/full_reading.md` 等で生成される実運用の出力は、この Gold Standard と**同等以上の厳密さ**を満たすべき、という基準になる
- 将来 `tests/`（テストフレームワーク）を構築する際、Gold Standard は「期待される出力の見本（フィクスチャ）」として使う想定（未着手）

---

## 2. 位置づけ（既存文書との関係）

| ファイル | 役割 |
|---|---|
| `ENGINE_DESIGN_v1.0.md` | 「何が高品質な分析か」を定義する設計書（規則） |
| `templates/full_reading.md` | 実運用でリーディングを生成するための**出力フォーマット**（型） |
| `GOLD_STANDARD_TEMPLATE.md`（本ディレクトリ） | Gold Standard 実例を作るための**13セクション構成**（型） |
| `GOLD_NNN_*.md`（本ディレクトリ） | 実際に埋めた**理想出力の実例** |
| `logs/QA_CHECKLIST.md` | 出力が基準を満たしているかを**採点する**チェックリスト |

`GOLD_STANDARD_TEMPLATE.md` は `templates/full_reading.md` を置き換えるものではない。
`full_reading.md` は「日常運用でLLMが埋める型」、`GOLD_STANDARD_TEMPLATE.md` は
「その埋め方の模範解答を作るための、より詳細な13セクション型」という関係にある。

---

## 3. 重要な設計上の注意（GOLD_001 を読む前に）

Fortune-OS は現時点で、占術データを**意図的にすべて未計算**にしている（`ROADMAP.md` v0.1〜v0.2.5の方針）。
そのため、`GOLD_001_NAOATSU.md` の「宿命分析」等のセクションは、**豊富な確定的記述にはならない**。

これは欠陥ではない。**Gold Standard の品質は「占術がどれだけ雄弁か」ではなく、
「計算していないことをどれだけ誠実に扱い、それでもどれだけ深い分析ができるか」で測る。**
未計算のまま断定してしまえば一見「豪華な」読みが書けるが、それは `CLAUDE.md` §3-3 の最重大違反であり、
Gold Standard としては**失格**になる。

## 6. 品質基準（このファイルが満たすべきこと）

`GOLD_NNN_*.md` は以下を満たさなければ Gold Standard を名乗れない：

- 一般論を書かない（対象者の実際の職業・関心・状況に紐づく具体性がある）
- 根拠のない断定をしない（すべてタグ付き。出典のない `[計算済]` を名乗らない）
- 占術と心理学を混ぜない（別レンズとして独立に記述する）
- 必ず統合する（統合は「セクション9」等、明示された統合ステップでのみ行う。文中で暗黙に混ぜない）
- 行動提案は具体的にする（最低3選択肢、各選択肢に可逆性・最悪ケース・撤退条件・トリガー条件）
- 現実で検証できる形にする（何が分かれば当たり外れを判定できるかを明記する）
