## 0. 総評

設計思想（7レイヤー分離／未計算の明示／断定禁止／辛口だが人格否定なし／意思決定支援が目的）は
全ファイルで方向性が揃っており、骨格として完成度が高い。占術データを意図的に全部「未計算」にした判断も正しい。

一方で、**「ルールを規定するファイル同士」の整合性**に穴がある。とくに
①権威（優先順位）の二重定義、②タグ付け規約の適用範囲の未定義、③「未計算/未検証」の意味の混同、
④テーマ数（4 vs 6）の不一致、は v0.3 前に潰しておくべき。

分類の目安：
- **Critical** … ルール体系の根幹が自己矛盾しており、LLM が衝突を解決できない
- **Major** … 一貫性・再現性を損なう。放置すると出力品質が不安定化する
- **Minor** … 局所的な表記ゆれ・DRY 違反・軽微な誤タグ

## Critical

### C1. 最上位権威の二重定義（CLAUDE.md ⇔ system_prompt.md）

**該当**
- `CLAUDE.md` 冒頭：「他のどのファイルよりも先に読み、これに従う…本ファイルの禁止事項が優先する（`safety_rules.md` のみ同格）」
- `system/system_prompt.md` L4：「LLM に対する**最上位の指示**。他のどのファイルの内容よりも、ここでの禁止事項が優先される」
- `system/system_prompt.md` §8：優先順位を「`safety_rules` > 本ファイル > `output_rules`/`quality_rules` > …」と定義（**CLAUDE.md が並びに存在しない**）
- `system/safety_rules.md` §7：「`safety_rules.md` ＝ `CLAUDE.md` ＞ その他すべて」
- `CLAUDE.md` §6 読む順序：CLAUDE → safety → system_prompt …（safety を2番目に置くが、同格なら1番目相当のはず）

**問題**
CLAUDE.md と system_prompt.md が**どちらも「最上位」を自称**している。さらに system_prompt.md §8 の優先順位表に CLAUDE.md が入っておらず、3ファイルで権威関係の記述が食い違う。ルール体系の頂点が曖昧＝ルールが衝突したとき LLM が解決不能。これは占い OS の心臓部の欠陥。

**修正案（具体）**
1. 権威の単一ソース化。次の1つの序列に統一し、全ファイルがこれを**参照**する形にする：
   ```
   [0] safety_rules.md  … 安全は常に最優先（CLAUDE と同格・衝突時は安全を選ぶ）
   [1] CLAUDE.md        … プロジェクト最上位ルール
   [2] system_prompt.md … 実行時のコア指示（CLAUDE.md に従属）
   [3] output_rules.md / quality_rules.md
   [4] user/ → astrology/ psychology/ strategy/ → knowledge/ → templates/
   ```
2. `system_prompt.md` L4 を「本ファイルは `CLAUDE.md` と `safety_rules.md` に従属する。両者と衝突した場合は上位が優先」に書き換え、「最上位」表現を削除。
3. `system_prompt.md` §8 の並びに `CLAUDE.md` を明記（`safety_rules = CLAUDE > system_prompt > …`）。
4. 「同格」の意味を1箇所で定義：「safety と CLAUDE は同格。両者が衝突する事態は想定しないが、起きたら安全側に倒す」。
5. `CLAUDE.md` §6 の読む順序と、この優先順位が**別軸**（読む順 ≠ 強さ順）であることを明記し、混同を防ぐ。

## Major

### M1. 7レイヤータグの「適用範囲」が未定義

**該当**
- `CLAUDE.md` §2 / `system_prompt.md` §1 / `output_rules.md` §1B：「**すべての実質的記述**にタグを必ず付ける」
- 実際にタグを使っていないファイル：`knowledge/*`（理論）、`docs/*`、`system/*`（ルール自身）、`ROADMAP.md`、`CHANGELOG.md`

**問題**
規約は「全記述にタグ必須」と全称で書かれているが、meta（ルール）・理論・ドキュメント系はタグを付けていない（付けるべきでもない）。**明文の除外規定がない**ため、LLM が「knowledge の理論文にもタグを振る」か「どこにタグが要るのか」で揺れる。中核規約の適用境界が未定義。

**修正案**
- `system_prompt.md` §1 と `output_rules.md` §1 に**適用範囲**を追記：
  > 7レイヤータグは「**対象者に関する分析・リーディング出力**」に適用する。具体的には `user/`、`astrology/`・`psychology/`・`strategy/` の“適用”記述、および `templates/` に沿った実出力。
  > 一方、`system/`・`docs/`・`knowledge/`・`ROADMAP`・`CHANGELOG` は**ルール／理論／メタ情報**であり、タグ対象外。理論の中で人物に適用した瞬間からタグが要る。
- `knowledge/README.md` は既に「理論であって解釈ではない」と書けているので、そこへ「ゆえにタグ対象外」の一文を足すと整合。

### M2. 「未計算」と「未検証」の混同

**該当**
- `docs/glossary.md` §1：「未計算 / 未検証 | 実際に計算・確認していない占術データに付けるラベル」（両者を1行に同義的にまとめている）
- `output_rules.md` §1A・`templates/full_reading.md` §0：四柱・大運・ハウス等を「（すべて**未検証**）」と表記
- `user/subject.md` §3：出生時刻を「**未検証**」、四柱を「**未計算**」と（正しく）区別

**問題**
本来この2語は意味が違う：
- **未計算** = まだ計算していない（例：四柱・ホロスコープ）
- **未検証** = 値/前提が確認できていない（例：出生時刻＝本人申告で裏取り前）

ところが output_rules / full_reading では、未計算であるはずの四柱・ハウスを「未検証」と書いており、区別が崩れている。「全部を分ける」という OS の理念に反する混同。

**修正案**
- `glossary.md` を2行に分割し定義を明確化：
  > 未計算：まだ計算していない占術データ（計算すれば値が出る）。
  > 未検証：値・前提が一次情報で確認できていない（例：出生時刻、他者申告の生年月日）。値は仮に使うが信頼度を下げる。
- `output_rules.md` §1A の例を「四柱・大運・年運・ハウス・アスペクト（すべて**未計算**）／出生時刻（**未検証**）」に修正。
- `templates/full_reading.md` §0、`annual_reading.md` §0、`compatibility_reading.md` §0 も同基準に統一。

### M3. 重点テーマ数が 4 と 6 で不一致

**該当**
- `user/subject.md` §2：**6項目**（仕事・創作/技術探究・独立適性・組織との関係・後半戦・夫婦）
- `user/priorities.md` §2：**4テーマ**（仕事・創作・夫婦・後半戦）＋「付随：独立適性・組織との関係」
- `templates/full_reading.md` §1：6項目を列挙、§4：4テーマで構成
- `quality_rules.md` §1・`README.md`・`CLAUDE.md`：自己採点で「**本人の4テーマ**に接続しているか」

**問題**
「4テーマ」という語が自己採点チェックリスト（quality_rules）に入っているのに、どれが4つかがファイルごとに違う。LLM が「4テーマに接続」を検証しようとしても基準が定まらない。

**修正案**
- 正典を priorities.md に一本化：**コア4テーマ＝仕事／創作・技術探究／夫婦関係／人生後半戦**。**独立適性・組織との関係は「仕事」に内包する付随テーマ**、と定義。
- `subject.md` §2 と `full_reading.md` §1 を「コア4＋付随2」の階層表記に統一。
- `quality_rules.md`・`CLAUDE.md`・`README.md` の「4テーマ」に (`priorities.md` §2 参照) を付す。

### M4. ROADMAP の v0.2 チェックリストが実態と乖離

**該当**：`ROADMAP.md`「v0.2」節
- [ ] `quality_rules.md` を実運用レベルに → 実際は自己採点表・信頼度基準まで**記述済み**
- [ ] `safety_rules.md` を具体化 → 医療/法律/財務/破滅予言/危機対応まで**記述済み**
- [ ] `docs/*` を本文化 → philosophy/methodology/glossary **本文化済み**
- [ ] `templates/` 残り3種を実用化 → annual/compatibility/decision_support **作成済み**

**問題**
v0.2 で「これからやる」とされた項目の大半が、すでに v0.1 コミットで実装されている。進捗表が実態を反映しておらず、次に何をやるべきかの判断を誤らせる。

**修正案**
- v0.2 の完了済み項目を [x] に更新し、本レビュー（REVIEW_v0.2.md）で洗い出した C1〜M8 の修正を**新しい v0.2 の実体**として再定義する。
- v0.2 = 「整合性の確定（本レビュー対応）」、v0.3 =「実計算」と役割を明確化。

### M5. README「使い方」が CLAUDE.md を読み込ませていない

**該当**：`README.md`「使い方」§1「`system/system_prompt.md` をシステムプロンプトとして読み込ませる」
**問題**：CLAUDE.md は「最優先・最初に読む」と宣言されているのに、使い方の手順に登場しない。運用手順と権威定義が食い違う。
**修正案**：手順を
1. `CLAUDE.md` を最優先ルールとして読み込ませる → 2. `system/`（safety→system_prompt→output/quality）→ 3. `user/` → 4. `templates/`
に修正し、C1 の優先順位と一致させる。

### M6. 位置情報（サイン/度数/柱）が「占術解釈」タグになっている

**該当**
- `user/subject.md` §3-2：「太陽サイン：`[占術解釈]` 3月23日は牡羊座…」
- `astrology/western_astrology.md` §2、`user/wife.md` §2-2 も同様

**問題**
「太陽がどのサインにあるか／どの柱か」は**位置の計算結果**であって、占術体系の“読み”（＝解釈）ではない。現状は位置事実と解釈が同じ `[占術解釈]` タグに同居しており、v0.3 で実際の度数・命式を入れる段になると、「位置＝計算済」「意味＝占術解釈」の切り分けが破綻する。

**修正案（v0.3 前に確定すべき規約）**
- 規約を1つ足す：
  > 天体・柱の**位置そのもの**（サイン・度数・干支）は、計算・出典があれば `[計算済]`。位置の**意味づけ・気質の読み**が `[占術解釈]`。
- 現状の太陽サインは概算のため、暫定的に「`[計算済(概算)]` 太陽＝牡羊座付近（境界のため確定は未計算）」と表記し、意味の読みだけ `[占術解釈]` に回す。
- この規約を `output_rules.md` §3（数値の扱い）に追記。

### M7. 辛口トーンと「未検証の推測」の橋渡しルールがない

**該当**：`CLAUDE.md` §4・`system_prompt.md` §4・`docs/philosophy.md` §5（辛口・本質を突く）と、`psychology/*`（多くが `[推測]`＋`未検証`）
**問題**
「辛口で本質を突く」ライセンスと、「実データがなく推測・未検証」という現状が、橋渡しルールなしに同居している。**未検証の推測に対して辛口に断ずる**のは、未来断定禁止と同じく“軟らかい断定”になりうる。トーンの強さと証拠の強さの対応関係が明文化されていない。

**修正案**
- `system_prompt.md` §4（または `quality_rules.md`）に一文追加：
  > 辛口の強度は**証拠の強度に比例**させる。`[現実照合]` で裏の取れた構造・行動には遠慮なく踏み込んでよい。`[推測]`・`未検証`段階の事柄は、辛口にせず仮説として提示する（「〜の可能性／構造がありうる」）。断定的に人格や傾向を刺すのは現実照合後。
- `quality_rules.md` §3 レッドフラグに「未検証の推測を辛口に断じている」を追加。

### M8. 実計算の設定規約と `[計算済]` 出典書式が未定義

**該当**：`system_prompt.md` §1（`[計算済]` は「出典・計算方法を併記」）だが、**何をどう書くかの雛形がない**。`astrology/*` §5 の「解消手順」も設定条件に触れていない。
**問題**
v0.3 で実計算した瞬間、再現性の要となる設定（下記）が未定義だと、計算結果が検証不能・体系間で不整合になる。
- 西洋：タイムゾーン（JST=UTC+9）、サマータイム有無（YYYY/YYYY の日本は無）、黄道（トロピカル/サイデリアル）、ハウスシステム（Placidus 等）
- 四柱：時差・真太陽時補正の有無、節入り（立春等）の扱い、時柱の子刻境界
- 六星系：採用する体系名（商標「六星占術」か類似か）と算出根拠

**修正案（v0.3 前に用意）**
- `knowledge/calculation_config.md` を新設し、上記の採用設定を1枚に固定（例：JST 固定・DST 無・トロピカル・Placidus・節入りは万年暦準拠、と明記）。
- `[計算済]` の出典書式テンプレートを `output_rules.md` §3 に追加：
  > `[計算済(出典:○○ソフト/万年暦, 設定:JST・Placidus・トロピカル, 算出日:YYYY-MM-DD)]`
- `astrology/*` §5 の解消手順に「設定を calculation_config に従い固定」を1行追加。

## 良かった点（維持すべき設計）

- 占術データを**意図的に全部「未計算」**に統一し、断定の余地を最初から塞いだ判断。
- テンプレートの相互参照（`decision_framework.md`・`cognitive_bias.md §4`・`relationships.md §5`・`user/*.md §4` 等）が実在の節を正しく指しており、リンク切れがほぼ無い。
- 「現実照合が最上位／占術は反証に落とす」という優先原則が philosophy・system_prompt・decision_framework で一貫。
- `knowledge/`（人物非依存の理論層）と適用層の分離という v0.1 追加の設計が、拡張の土台として妥当。
